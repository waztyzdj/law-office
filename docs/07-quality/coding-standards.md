# 编码规范

项目编码规范分前后端维护：

- 前端规范：`frontend/AGENTS.md`
- 后端规范：`backend/AGENTS.md`

## 文档维护要求

- 修改接口：同步 `docs/04-api/`。
- 修改数据库：同步 `docs/03-database/`。
- 修改功能行为：同步 `docs/01-requirements/` 和 `docs/05-modules/`。
- 修改部署配置：同步 `docs/06-deployment/`。

## 基本原则

- 先复用项目已有模式。
- 保持最小范围修改。
- 高风险变更必须验证。
- 公共能力变更必须扩大验证范围。修改前端公共组件、公共 hooks、请求层、路由、权限、store、全局样式，或后端框架基类、拦截器、租户/权限/分页等横向能力时，必须先说明影响面，并抽样验证多个既有调用方，不能只验证当前需求页面或只依赖编译通过。
- 代码、接口、数据库、文档四者保持一致。
- 涉及数据库字段枚举、状态码或字段含义时，必须以 `sql/建表脚本.sql` 的字段注释为准，再同步前端、后端、初始化 SQL 和文档。
- 后台业务接口遵循当前框架约定，默认使用 `POST + body` 传参，`id` 不写在路径中；新增 RESTful path 参数接口前必须确认属于文件、预览、公开回调等资源型场景，并同步说明原因。
- 业务域路径和权限码前缀必须跟业务包一致；例如工作流域统一使用 `/workflow` 和 `workflow:*`，不得保留旧的 `/workflow/approval` 或 `approval:*`。
- 前端业务列表使用 `defineTableColumns` 时必须配置稳定且模块唯一的 `tableKey`，用于隔离列宽持久化缓存；禁止不同列表共用默认列宽命名空间，避免同名列（如 `action`、`status`）互相污染宽度。

## 后端 Service 约定

- 业务 Service 必须按接口和实现拆分，接口放在 `service` 包并以 `I` 开头，实现放在 `service.impl` 包并以 `Impl` 结尾。
- 标准 CRUD Service 接口继承 `IBaseService<E, V>`，实现继承 `BaseServiceImpl<M, E, V>`；非 CRUD 的协作服务也必须提供接口和实现，调用方优先依赖接口。
- 不把可复用的业务协作能力直接写成无接口的 `Service` 类；例如租户上下文执行、默认数据同步、用户-租户关系同步、授权范围校验等，都应优先抽成接口 + 实现。
- 应用 Service 负责组织业务流程和事务边界；关系同步、默认数据复制、权限范围校验等协作逻辑应沉淀为清晰命名的协作 Service，避免堆在单个实现类中。

## 代码注释约定

- Service 接口的公共方法必须写 JavaDoc，说明业务语义、关键约束、参数和返回值。
- 实现类中不在接口里的 `private` 方法，凡是承载业务规则、数据同步、权限校验、租户上下文切换、软删恢复或复杂查询组装的，必须写方法级注释。
- 关键代码分支要说明“为什么这样做”，例如：为什么逻辑删除而不物理删除、为什么恢复已删除关系而不重复插入、为什么授权不能超过当前操作人权限、为什么默认数据同步不覆盖租户已有数据。
- 简单 getter/setter、纯粹一眼可读的局部变量赋值不需要机械注释；禁止写只复述代码的空泛注释。

## 代码 Review 约定

以后执行代码 review 时，除常规 bug 和回归风险外，必须重点检查以下内容：

- 编码规范：前端是否符合 `frontend/AGENTS.md`，后端是否符合 `backend/AGENTS.md`，跨端行为、接口和数据库字段含义是否与 `sql/建表脚本.sql`、接口文档和模块文档一致。
- 注释质量：公共接口、复杂私有方法、权限边界、租户隔离、软删恢复、文件归类、对象存储和跨模块扩展点是否有必要且清晰的注释；删除只复述代码、过时或误导性的注释。
- 冗余和废弃代码：检查未使用导入、未使用常量、重复分支、遗留调试代码、临时 mock、无效样式、废弃接口和已被新实现替代的代码；确认无业务价值后直接清理。
- 主流设计一致性：检查实现是否复用项目现有组件、Service、API 封装、文件中心能力和业务文档 Provider 扩展点，避免为单个业务模块硬编码定制逻辑。
- 安全和数据边界：重点检查租户隔离、所有者校验、共享授权继承、业务文档访问校验、上传白名单、下载鉴权、回收站和彻底删除清理范围。
- 前端交互完整性：复杂页面要检查 loading、empty、disabled、右键菜单、快捷键、拖拽、多选、重命名、长文本、窄屏和本地缓存失败兜底。
- 公共前端能力回归：涉及 `BaseTable`、`useTable`、`defineTableColumns`、全局样式、请求封装、路由守卫、权限工具等改动时，必须抽样检查系统管理页、当前业务页和另一个业务模块页，重点验证分页、筛选、排序、操作列、权限按钮、滚动和空状态。
- 文档同步：功能行为、接口协议、数据库字段、公共扩展点或编码约定发生变化时，必须同步 `docs/` 和对应 `AGENTS.md` 或本规范。

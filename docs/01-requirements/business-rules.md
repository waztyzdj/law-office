# 关键业务规则

## 用户

- 用户名不能为空，新增后不允许通过普通编辑接口修改。
- 新增用户必须提供密码。
- 密码需要满足复杂度要求：8-20 位，包含大小写字母、数字和特殊字符。
- 手机号、邮箱、工号、身份证号等字段在未删除用户中保持唯一。
- 密码字段不得在普通查询和导出中返回。

## 认证

- 登录成功后返回 token 和默认租户 ID。
- 用户可关联多个租户，只能切换到已分配且状态正常的租户。
- 切换租户必须由后端重新签发携带目标租户 ID 的 token。
- 登录前会清理同一用户旧 token，保证会话状态可控。
- 登出时清理 Redis 中的 token 信息。
- 修改密码必须校验旧密码。

## 权限

- 用户权限由角色权限汇总得到。
- 菜单权限和按钮权限统一存储在 `sys_permission`。
- 前端按钮权限和后端接口权限必须同步。
- 租户编码新增后不能修改。
- 新建或保存租户后，系统会自动确保该租户存在默认 `租户管理员` 角色，角色编码为 `ADMIN_ + 租户编码`；租户管理员成员通过租户管理页面维护。
- 平台管理员不自动成为每个租户的管理员；租户管理员角色默认不自动授权，需要通过租户管理的管理员授权入口维护，授权不能超过当前操作人自身可下放权限。
- 自定义角色编码不能以 `ADMIN_` 开头。
- 角色授权必须受操作者自身权限约束，不能给角色授予超出自身范围的权限；系统默认角色编码为 `ADMIN` 的超级管理员角色除外。

## 数据

- 业务表默认使用逻辑删除，查询过滤 `delete_flag = 0`。
- 多租户数据必须带租户字段并通过租户上下文隔离。
- 删除租户时同步逻辑删除租户用户关系、租户角色、角色权限和角色用户关系；用户主账号不随租户删除。
- 新建租户时复制默认租户 `0` 的数据字典、字典项和通用类型；默认租户 `0` 新增这些数据时补齐到所有启用租户。
- 审计字段由后端统一填充，不信任前端传入的创建人、修改人。
## 租户授权补充规则

- 租户管理支持直接为目标租户的默认管理员角色设置权限，避免平台管理员必须先切换到目标租户才能授权。
- 租户管理员角色授权不能超过当前操作人自身权限，且不下放租户管理、权限管理等平台级能力。
- 角色编码为 `ADMIN` 的超级管理员可以切换到任一启用租户，切换后默认叠加目标租户 `ADMIN_ + 租户编码` 角色权限；普通用户只能切换到已分配且启用的租户。

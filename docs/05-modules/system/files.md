# 文件管理

## 功能说明

文件管理用于维护文件元数据和业务关联，并与 MinIO 对象存储能力配合。
第一期文档中心在此基础上提供用户个人文档、租户内共享和回收站能力。

## 代码入口

- Controller：`backend/src/main/java/com/lawoffice/system/controller/SysFilesController.java`
- Service：`backend/src/main/java/com/lawoffice/system/service/impl/SysFilesServiceImpl.java`
- Entity：`backend/src/main/java/com/lawoffice/system/entity/SysFiles.java`

## 数据表

- `sys_files`：文件元数据
- `sys_file_version`：文件历史版本
- `sys_file_acl`：文件访问授权
- `sys_file_relation`：文件与业务对象的关联

## 接口前缀

- `/files`
- `/files/document`

## 关键规则

- 文件元数据和业务关联分离。
- 文件对象由服务端生成 key。
- 所有上传、查询和绑定操作都应校验租户与文件状态。
- 通用附件单文件大小上限为 50MB，超过限制时返回 413。
- 文档中心上传采用文件类型白名单，仅允许常规文档、图片和视频文件，禁止上传可执行文件、脚本和压缩包等高风险类型。
- 文件中心通用详情和下载接口仅允许上传人访问；受保护业务附件必须通过对应业务模块接口下载，并由业务模块校验成员、收件人、审批人等访问权限。
- 文件下载由后端按 `sys_files.file_name` 设置下载文件名，避免暴露对象存储 key 或产生中文乱码。
- 文档中心使用 `sys_files.parent_id` 表示文件夹层级，`iz_folder=1` 表示文件夹。
- 文档中心共享使用 `sys_file_acl`，目标类型为 `user`、`depart`、`role`、`tenant`，权限为 `read`、`download`、`update`、`manage`。
- 在线编辑历史版本使用 `sys_file_version` 保存不可变 MinIO 对象。上传支持历史预览的文档时生成 `upload` 初始版本；ONLYOFFICE `status=6` 强制保存只覆盖当前文件，不生成历史版本；`status=2` 最终保存按 SHA-256 去重后生成 `final` 版本。
- 历史版本只允许只读预览，不允许编辑历史版本本身；恢复历史版本需要当前文件 `update/manage` 权限，恢复后覆盖当前文件并新增 `restore` 类型版本记录。
- 文档中心第一期支持“我的文档、业务文档、租户共享、部门共享、共享给我、我的共享、我的收藏、回收站”；上传、新建文件夹、重命名、移动、删除、恢复和共享仅允许文件拥有者操作；复制粘贴允许复制当前用户可下载的文件或可访问文件夹，并为文件副本生成新的对象存储文件。
- 回收站中不支持重命名、收藏和共享；文件所有者可执行恢复、彻底删除或清空回收站，文件夹移入回收站后保留原有层级，根目录只展示已删除文件夹树的顶层节点，彻底删除会同步清理授权、个人归类关系和对象存储文件。
- 租户共享、部门共享和我的共享支持上传文件和新建文件夹；共享给我不支持上传文件，但支持新建个人整理文件夹，并可把共享给我的文件拖入个人整理文件夹归类。
- 共享给我的个人归类复用 `sys_file_relation` 记录当前用户的整理关系，不修改被共享文件原始 `parent_id`，避免影响文件所有者和其他共享成员。
- 我的收藏聚合展示当前用户已收藏且未删除的文件和文件夹；进入收藏文件夹后按该文件夹原有层级浏览其直接子级。
- “业务文档”是与“我的文档”平行的独立分类，用于展示当前用户有业务访问权且仍存在业务关联的文档；消息附件等业务文档按业务模块访问权展示，例如消息发件人和收件人均可查看。业务文档根目录先按业务模块展示虚拟文件夹（`store_type=business_module_view`），进入模块后再按业务数据核心字段展示虚拟文件夹（`store_type=business_record_view`），进入具体业务数据后展示附件和个人整理文件夹。业务附件不允许在文档中心上传、重命名或删除，只有业务数据解除附件关联后才能回到普通文档流程清理。
- 用户头像等系统内部附件不进入业务文档分类；需要排除的内部附件业务类型必须在文档中心服务中集中维护，避免散落在各业务 Provider 中。
- 业务文档只允许在具体业务数据目录或个人整理文件夹下创建和重命名个人整理文件夹，整理文件夹使用 `store_type=business_view`；拖拽归类通过 `sys_file_relation` 的 `relation_type=3`、`biz_type=document_business:<userId>` 记录，不修改业务附件原始 `parent_id`。
- 业务文档接入点是 `IBusinessDocumentProvider`。新增业务模块只需要继续使用 `sys_file_relation.biz_type/biz_id` 绑定附件，并实现 Provider 返回模块名称、业务数据目录名称和访问权限判断；文档中心不应新增面向具体业务模块的 `if/else` 定制逻辑。
- 文档中心左侧搜索为全局搜索，按当前用户查询权限检索本人未删除文件、被共享文件以及被共享文件夹下的子级文件，结果展示在右侧区域。
- 租户共享和部门共享会同时展示当前用户接收的共享文件以及本人共享到该目标的文件；本人可在共享目标根目录新建共享文件夹，并可将本人共享文件移动到本人拥有的共享文件夹中整理归类。
- “共享给我”支持打开被共享文件夹并浏览其子级；下载必须具备 `download` 及以上权限且文件未禁用下载。
- 前端支持图标和列表两种浏览模式，浏览模式缓存到本地；两种模式都必须保持单击选中、双击打开或下载、右键菜单、拖拽、多选和剪切虚化等操作系统式交互一致。
- 文档中心快捷键按主流操作系统习惯实现：`Ctrl/Command + X` 剪切、`Ctrl/Command + C` 复制、`Ctrl/Command + V` 粘贴、`Delete` 删除，macOS 同时支持 `Command + Backspace` 删除；`Ctrl/Command + 单击` 支持间隔多选，`Shift + 单击` 支持连续多选。
- 文档中心作为通用能力，不做 `files:view`、`files:edit` 功能权限拦截；权限边界由租户、所有者和共享授权数据规则控制。

# 审批中心二期需求明细

## 文档目的

本文用于把审批中心二期设计范围拆成可开发、可验收的需求条目。后续数据库设计、接口设计、前端改造、后端实现和测试用例必须先对齐本文，再进入编码。

二期范围以 [审批中心二期设计文档](approval-center-phase2-design.md) 为准。本文补充每个功能的业务规则、边界和验收场景。

## 总体目标

二期在一期审批闭环基础上增强流程结构和协同能力：

- 支持条件分支、会签、或签，让流程不再只依赖顺序审批。
- 支持抄送、撤回、催办、超时提醒，补齐日常审批操作。
- 支持审批消息、附件和业务文档中心联动，减少审批信息割裂。
- 支持流程图高亮和 BPMN XML 安全校验，提升运行态可读性和发布安全。

## 总体边界

- 二期必须兼容一期顺序流程，不能破坏发起申请、待办、已办、我发起的、审批详情、审批记录、通过、不通过、退回、转办、加签和字段权限。
- 二期不实现审批模板复制、流程版本迁移、管理员干预、统计报表、监控大屏、移动端适配、打印导出归档和外部系统回调。
- 二期不开放任意脚本、任意外部服务任务、任意表达式执行和未审核监听器。
- 二期消息通知只做站内消息；短信、邮件、企微、钉钉等外部通知如需接入，放到后续集成设计。
- 二期超时提醒只提醒，不自动同意、不自动拒绝、不自动跳过、不自动升级。
- 二期移动端只保证现有响应式页面不被明显破坏，不做独立移动端审批体验。

## 通用业务规则

- 所有新增数据必须包含租户隔离字段，并遵循 `delete_flag` 逻辑删除和审计字段规则。
- 所有新增接口继续使用 `/workflow` 前缀，后台业务接口使用 `POST + body`，不新增 RESTful path 参数接口。
- 审批详情访问权在一期基础上扩展抄送人、附件相关授权人，但最终仍以后端校验为准。
- 审批动作必须写入审批记录或专项记录，不能静默改变流程状态。
- 新增动作、状态、节点类型、任务类型、办理策略、提醒策略等枚举必须同步 SQL 注释、后端常量、前端常量、接口文档和模块文档。
- 所有人员选择必须复用统一用户选择器，并由后端校验当前租户有效用户，不能信任前端传入 ID。
- 二期涉及附件时必须复用文件模块，涉及业务文档访问时必须通过业务文档 Provider 校验访问权。
- Flowable 仍只作为运行时引擎，前端列表、租户过滤、业务状态和详情展示以 `wf_*` 扩展表为准。

## 条件分支

### 业务规则

- 条件分支用于按运行时数据选择后续流转路径。
- 条件来源二期支持：
  - 表单字段值。
  - 发起人本人。
  - 发起人所属部门。
  - 发起人角色。
  - 流程实例基础字段，例如流程编码、流程分类。
- 表单字段条件二期支持常见比较：
  - 文本：等于、不等于、包含、不包含、为空、不为空。
  - 数值：等于、不等于、大于、大于等于、小于、小于等于、区间。
  - 日期：早于、早于等于、晚于、晚于等于、区间。
  - 单选：等于、不等于、属于、不属于。
  - 多选：包含任一、包含全部、不包含。
  - 布尔：为真、为假。
- 每个条件分支必须配置优先级。
- 多个分支命中时，按优先级选择第一个命中的分支。
- 条件分支必须配置默认分支；没有任何条件命中时走默认分支。
- 条件表达式由后端按已发布流程模型和表单快照执行，不能由前端传入计算结果。
- 定义侧条件必须保存为结构化 `branch_json`；BPMN 条件表达式只允许使用系统分支变量占位，不允许任意脚本或 JUEL 表达式。
- 发布流程时必须校验每条分支都连接到有效节点，且最终可到达结束节点。
- 分支判断发生在上一个节点完成后、生成下一批待办前。
- 条件判断结果必须可追溯，至少能在日志或审批记录中定位命中的分支。

### 边界

- 二期不支持用户自定义脚本表达式。
- 二期不支持跨表查询、外部接口查询和复杂公式计算。
- 二期不支持并行多分支同时命中后同时流转；多分支命中只走优先级最高的一条。
- 条件字段如果在表单快照中不存在，发布时应阻断；历史实例仍按发起时快照判断。
- 条件字段值为空时，只能命中明确配置的“为空”或默认分支。
- 审批中可编辑字段被修改后，后续条件判断读取当前 `wf_form_instance.form_data_json`。

### 验收场景

- 配置金额小于等于 10000 走部门负责人，大于 10000 走合伙人，分别发起两条申请，流程进入不同节点。
- 配置两个条件同时命中，验证按优先级走第一条命中分支。
- 配置没有命中的条件，验证走默认分支。
- 发布缺少默认分支的流程，后端拒绝发布。
- 发布引用不存在表单字段的条件，后端拒绝发布。
- BPMN 流程包含排他网关但没有对应网关节点配置时，后端拒绝发布。
- 审批节点修改可编辑字段后再通过，后续分支按修改后的字段值判断。
- 普通一期顺序流程不配置条件分支时，仍按原链路正常结束。

## 会签

### 业务规则

- 会签表示同一审批节点有多个办理人，需满足完成策略后才能进入下一节点。
- 二期默认实现全员通过策略：所有会签办理人通过后，节点完成。
- 会签节点审批人来源复用一期审批人解析能力，支持指定人员、指定角色、部门负责人、部门岗位、发起人直属上级、审批人自选。
- 会签节点如果解析出多名审批人，应为每个办理人生成独立待办。
- 会签节点的当前处理人摘要展示所有未完成会签人。
- 会签办理人的审批意见都必须进入审批记录。
- 会签节点未完成前，流程实例状态仍为 `running`。
- 会签节点所有人通过后，才生成下一节点待办。
- 会签节点不通过策略二期先采用“任一人不通过则流程不通过并结束”，如果后续需要“仅记录反对但继续等待”，另行设计。
- 会签任务支持转办、退回、加签的规则需要以节点动作权限为准，但同一会签节点内任一人退回或不通过后，其它未完成会签任务必须取消。

### 边界

- 二期会签只实现并行会签；串行会签场景使用多个普通审批节点表达。
- 二期不支持通过比例策略作为默认交付项；如要支持，必须先补充比例字段、展示和验收。
- 二期不支持会签中动态追加多名会签人；现有加签仍按一期加签子任务语义处理。
- 二期不支持会签节点内审批人重复，后端必须按用户 ID 去重。
- 会签节点不能没有有效审批人；运行时解析为空时，按一期审批人自选兜底。
- 会签任务不能因其中一个办理人打开详情而锁定其它办理人。

### 验收场景

- 配置 3 人会签，3 人都通过后才进入下一节点。
- 配置 3 人会签，第 1 人通过、第 2 人未处理时，下一节点没有待办。
- 配置 3 人会签，第 2 人不通过后，流程结束，其它未处理会签待办取消。
- 会签待办列表中每个会签人只能看到自己的待办。
- 会签审批详情中展示所有会签人的处理状态和审批意见。
- 会签节点某办理人转办后，新办理人可完成该会签任务，其它会签任务不受影响。
- 会签节点退回后，其它未完成会签任务被取消，流程回到目标节点或发起人重新提交。

## 或签

### 业务规则

- 或签表示同一审批节点有多个办理人，任一有效办理人完成后，该节点完成并进入下一节点。
- 或签节点必须显式配置，不能把一期“多人时由上一环节选择单人”误当成或签。
- 或签节点解析出多名审批人时，为每个办理人生成待办或候选任务，具体实现由运行时设计确定，但用户体验必须是多人都可处理。
- 首个有效办理人通过后，取消同一或签节点其它未处理任务。
- 首个有效办理人不通过时，流程按不通过结束，并取消同一或签节点其它未处理任务。
- 或签节点的审批记录必须展示实际办理人，并记录其它未处理任务被系统取消。
- 当前处理人摘要展示所有可办理或签人；节点完成后更新为下一节点处理人。

### 边界

- 二期不支持“至少 N 人通过”的复杂或签，这属于会签比例策略的扩展。
- 或签节点内用户必须去重。
- 或签节点不能和会签策略同时开启。
- 或签节点未处理人员被取消后，不能再从旧待办入口提交。
- 或签完成后再次收到重复提交请求时，后端必须拒绝或幂等处理，不能重复流转。

### 验收场景

- 配置 3 人或签，任一人通过后进入下一节点，其它两人的待办取消。
- 或签节点某人不通过后，流程结束，其它或签待办取消。
- 被取消的或签办理人打开旧详情时，只能查看，不能办理。
- 或签完成后，审批记录显示实际办理人和系统取消记录。
- 或签节点配置单人时，也能正常办理，不出现多余候选记录。

## 抄送

### 业务规则

- 抄送用于让非办理人查看审批详情，不参与审批流转。
- 抄送触发时机二期支持：
  - 发起后抄送。
  - 节点通过后抄送。
  - 流程结束后抄送。
  - 运行时手动抄送。
- 抄送对象二期支持：
  - 指定用户。
  - 指定角色。
  - 指定部门。
  - 发起人直属上级。
  - 运行时选择人员。
- 抄送记录必须落库，并作为审批详情访问权来源。
- 抄送人可查看表单快照、审批记录、附件和流程图，但不能看到办理按钮。
- 抄送消息应进入站内消息。
- 抄送不改变流程实例状态、任务状态和当前处理人。
- 重复抄送同一实例给同一用户时，应避免产生多条有效未读记录；可更新已存在记录的时间或保留一次有效记录。

### 边界

- 二期不实现抄送转办、抄送评论、抄送再抄送。
- 抄送人没有审批权限，不能通过接口执行通过、不通过、退回、转办、加签、撤回。
- 抄送人查看附件仍需通过后端访问权校验。
- 运行时手动抄送允许流程实例访问权用户在审批详情/办理页选择组织架构人员发起抄送；仅授予查看权，不产生待办，不改变流程状态，不允许按角色选择。
- 抄送对象解析为空时，不阻断主流程，但要记录可排查日志或提示配置异常。
- 抄送角色、部门解析结果必须过滤当前租户无效、冻结或已删除用户。

### 验收场景

- 流程发起后自动抄送给指定用户，该用户在“我的抄送”看到记录。
- 抄送人打开详情只能查看，不能办理。
- 抄送人访问未被抄送的实例，后端拒绝。
- 同一实例重复抄送给同一用户，不出现重复未读记录。
- 抄送角色下多个用户时，多个有效用户都收到抄送。
- 有权限查看实例的人手动抄送给多人后，对方进入“我的抄送”并可查看详情。
- 无实例访问权的人调用手动抄送接口时，后端拒绝。
- 抄送对象为空时，流程仍正常流转，并可排查到异常原因。

## 撤回

### 业务规则

- 撤回用于发起人在流程未被下一环节办理前收回申请。
- 二期仅允许发起人撤回自己发起的审批。
- 二期撤回条件：
  - 流程状态为 `running`。
  - 当前存在待办任务。
  - 当前待办未被下一审批人完成。
  - 流程未结束、未不通过、未终止。
- 撤回后取消当前待办和有效候选记录。
- 撤回后实例状态进入 `withdrawn` 终态，不在同一实例上生成重新提交任务。
- 撤回必须写审批记录，动作建议为 `withdraw`。
- 撤回必须发送消息给当前待办处理人和发起人。
- 已撤回实例在“我发起的”中可查看。

### 边界

- 二期不支持审批人撤回自己的审批意见。
- 二期不支持下一环节已办理后的强制撤回。
- 二期不支持管理员代发起人撤回，管理员干预放三期。
- 已结束、已不通过、已撤回、已终止流程不能再次撤回。
- 撤回和审批提交并发时，后端必须保证只有一个动作成功。

### 验收场景

- 发起后下一审批人未处理，发起人撤回成功，审批人待办取消。
- 下一审批人已通过后，发起人撤回失败。
- 非发起人调用撤回接口，后端拒绝。
- 已结束流程撤回，后端拒绝。
- 撤回后“我发起的”显示撤回或终止状态，审批记录包含撤回动作。
- 审批人打开被撤回的旧待办，只能查看撤回结果，不能继续办理。

## 催办

### 业务规则

- 催办用于提醒当前待办处理人尽快办理。
- 二期允许发起人对自己发起的运行中审批催办。
- 二期催办人范围先限定为发起人，不支持历史办理人催办后续节点。
- 催办对象为当前有效待办处理人和候选人。
- 催办只产生提醒消息和催办记录，不改变流程状态和任务状态。
- 催办必须防刷，建议同一实例同一任务在配置时间窗口内只能催办一次。
- 催办必须写入审批记录或专项催办记录，便于详情页展示。

### 边界

- 已结束、已不通过、已撤回、已终止流程不能催办。
- 没有当前待办的流程不能催办。
- 催办不自动转办、不自动升级、不自动跳过。
- 抄送人不能催办，除非后续单独授予权限。
- 催办消息发送失败不能改变审批主数据。

### 验收场景

- 发起人对当前审批人催办，审批人收到站内消息。
- 同一任务短时间重复催办，后端按规则拒绝或提示已催办。
- 已结束流程催办失败。
- 没有访问权的人催办失败。
- 会签节点催办时，所有未完成会签人收到提醒。
- 或签节点催办时，所有仍可办理的或签人收到提醒。

## 超时提醒

### 业务规则

- 超时提醒用于在任务超过配置时限后自动提醒处理人。
- 节点可配置超时时长，二期建议按自然时间计算。
- 超时起算时间为任务创建时间。
- 超时提醒对象为当前有效待办处理人和候选人。
- 超时提醒可配置提醒频率和最大提醒次数，避免重复刷屏。
- 超时提醒通道预留扩展字段，二期默认且仅开放站内消息提醒。
- 超时提醒只产生消息和提醒记录，不改变流程状态和任务状态。
- 任务完成、取消、退回、撤回、流程结束后，不再触发该任务超时提醒。

### 边界

- 二期不实现工作日历、节假日、工作时间段计算。
- 二期不实现超时自动同意、自动拒绝、自动升级、自动转办。
- 超时任务如果已被候选人认领，只提醒认领后的实际处理人。
- 超时配置为空或为 0 时，不触发超时提醒。
- 短信、邮件、企微、钉钉等提醒通道只保留配置扩展口，不在二期开放选择和发送实现。
- 定时任务重复执行时必须幂等，不能重复生成同一轮提醒。

### 验收场景

- 配置节点 1 小时超时，任务超过 1 小时后处理人收到提醒。
- 任务未超时时不提醒。
- 任务完成后即使超过原定时间也不提醒。
- 同一任务多次执行定时扫描，不重复生成同一轮提醒。
- 节点启用超时提醒但不选择提醒通道时，默认按站内消息发送。
- 会签节点只提醒未完成会签人。
- 或签节点在任一人完成后，其它已取消任务不再提醒。

## 审批消息通知

### 业务规则

- 二期审批动作触发站内消息，优先复用消息模块。
- 消息触发场景包括：
  - 新待办。
  - 通过。
  - 不通过。
  - 退回。
  - 转办。
  - 加签。
  - 抄送。
  - 撤回。
  - 催办。
  - 超时提醒。
  - 流程结束。
- 消息必须包含审批实例 ID、标题、动作类型、发送人、接收人、发生时间和前端跳转信息。
- 用户点击消息后进入审批详情，详情接口继续做访问权校验。
- 消息发送应尽量在审批主事务完成后执行；消息失败不应导致审批动作回滚。
- 消息内容应显示姓名、流程名称和实例标题，不显示裸 ID。

### 边界

- 二期只要求站内消息，不要求短信、邮件、第三方 IM。
- 消息不是权限来源，不能因为收到消息就跳过审批详情权限校验。
- 消息失败需要日志或失败记录，但二期不要求独立消息补偿后台。
- 历史实例不会补发二期上线前的消息。

### 验收场景

- 发起申请后，下一审批人收到待办消息。
- 审批不通过后，发起人收到结果消息。
- 退回后，目标办理人收到待办消息。
- 转办后，目标人员收到待办消息，原处理人不再拥有待办。
- 加签后，加签人收到待办消息。
- 抄送后，抄送人收到抄送消息。
- 撤回后，当前审批人收到撤回消息。
- 点击消息跳转详情，无权限用户仍被后端拒绝。

## 审批附件和业务文档中心联动

### 业务规则

- 发起人可在发起申请时上传审批附件。
- 审批人可在办理任务时上传审批附件，是否允许上传由节点配置或动作权限控制。
- 附件必须绑定审批实例，必要时同时绑定任务和操作记录。
- 附件上传、下载、预览和删除复用文件模块。
- 审批详情展示当前用户有权查看的附件。
- 已完成任务上传的附件默认随审批记录展示。
- 附件删除必须校验上传人、任务状态、实例状态和权限。
- 审批附件可同步或关联到业务文档中心，业务文档访问必须通过 `IBusinessDocumentProvider.canAccess(...)`。
- 流程结束后附件默认只读；如需归档到固定目录，放三期归档能力设计。

### 边界

- 二期不实现附件模板化，不实现自动生成归档 PDF。
- 二期不实现打印、导出、归档。
- 已结束流程默认不允许新增或删除附件，除非后续有管理员干预能力。
- 抄送人可查看附件，但不能上传或删除附件。
- 附件大小、类型和数量限制以文件模块统一配置为准；如果审批中心需要更细限制，进入数据模型设计阶段补字段。
- 删除附件不能物理删除文件中心对象，只解除审批附件关系或走文件模块既有删除策略。

### 验收场景

- 发起申请上传附件，审批人打开详情可查看和预览。
- 审批人办理时上传附件，后续节点和详情可查看。
- 无详情访问权用户下载附件失败。
- 抄送人可查看附件但不能删除。
- 非上传人删除办理中的附件，后端按权限拒绝。
- 流程结束后普通用户不能新增或删除附件。
- 业务文档中心访问审批附件时，后端调用业务文档访问校验。

## 流程图高亮当前节点

### 业务规则

- 审批详情提供流程图视图，展示节点、连线和运行状态。
- 节点状态至少包括：
  - 未到达。
  - 当前。
  - 已完成。
  - 已退回。
  - 已取消。
  - 已结束。
- 顺序流程、条件分支、会签、或签都必须能展示。
- 当前节点以后端 `wf_task(status=todo)`、候选记录和流程实例状态为准。
- 已完成节点以审批记录和任务完成记录为准。
- 退回路径必须能展示退回动作和目标节点。
- 流程已结束时高亮结束节点，不再显示悬空当前节点。
- 前端渲染所需节点和边由后端基于流程模型快照和运行时状态组装。

### 边界

- 二期只要求审批详情展示流程图，不要求流程监控大屏。
- 二期不要求实时动画和自动刷新。
- BPMN 复杂布局如果无法完全还原，至少要保证节点状态和路径关系正确。
- 历史流程按发起时流程模型快照展示，不读取最新草稿设计。

### 验收场景

- 顺序流程在第一审批节点时，高亮当前节点，发起节点显示已完成。
- 条件分支流程只高亮实际命中的路径，未命中分支显示未到达。
- 会签节点未全部完成时，会签节点显示当前，并展示多个处理人。
- 或签节点完成后，实际办理人路径显示完成，其它同节点任务显示已取消或不再作为当前。
- 退回后，图上能看出退回目标节点成为当前节点。
- 流程结束后，结束节点高亮，当前节点为空。

## BPMN XML 安全校验和白名单限制

### 业务规则

- 发布 BPMN 流程前必须执行 XML 结构解析和白名单校验。
- 二期允许的 BPMN 元素建议限制为：
  - `startEvent`
  - `endEvent`
  - `userTask`
  - `sequenceFlow`
  - `exclusiveGateway`
  - `parallelGateway`
  - 必要的 BPMN 图形元素
  - 项目明确允许的扩展属性
- 禁止的元素和配置包括：
  - `scriptTask`
  - `serviceTask`
  - `sendTask`
  - `receiveTask`
  - `businessRuleTask`
  - 事件监听器中的任意类名和表达式
  - 可执行脚本
  - 外部系统调用配置
  - 任意表达式执行
- 条件分支表达式必须使用项目自定义条件 JSON，不允许直接使用前端提交的任意 Flowable 表达式。
- 发布失败必须返回明确错误，说明第几个节点或哪类元素不允许。
- BPMN XML 必须限制大小，避免异常大文件拖垮解析。

### 边界

- 二期不开放 Flowable 的服务任务、脚本任务、DMN、CMMN、Form Engine。
- 二期不支持用户上传未经设计器生成的高风险 XML 直接发布。
- 对历史已发布流程不强制重新校验，但新发布版本必须按二期规则校验。
- 白名单校验不能只靠前端，必须在后端发布流程时执行。

### 验收场景

- 发布只包含开始、用户任务、顺序流、结束的 BPMN，校验通过。
- 发布包含排他网关的条件流程，校验通过。
- 发布包含脚本任务的 BPMN，后端拒绝。
- 发布包含服务任务的 BPMN，后端拒绝。
- 发布包含监听器类名或表达式的 BPMN，后端拒绝。
- 发布缺少节点配置的用户任务，后端拒绝。
- 发布超出大小限制的 BPMN XML，后端拒绝。

## 二期专项回归要求

二期开发期间，任何涉及 `workflow` 运行时、流程设计器、审批动作、任务同步、审批记录、消息、附件或权限校验的改动，都必须至少执行以下回归：

- 一期核心主链路：发起、待办、通过、不通过、退回、转办、加签、已办、我发起的。
- 条件分支主链路：命中分支、默认分支、发布校验失败。
- 会签主链路：全员通过、不通过终止、待办取消。
- 或签主链路：任一通过、其它待办取消、重复提交拦截。
- 抄送主链路：收到抄送、只读详情、无权限拒绝。
- 撤回主链路：可撤回、不可撤回、待办取消。
- 催办和超时提醒：消息生成、不改变流程状态、防重复。
- 附件主链路：上传、查看、预览、删除权限、无权限下载失败。
- 流程图：当前节点、结束节点、退回路径、条件路径。
- BPMN 安全：允许元素通过，禁止元素拒绝。

## 待确认事项

- 撤回后进入撤回终态，不生成发起人待提交任务。
- 催办人范围已确认：二期先仅限发起人。
- 抄送是否允许发起时手动选择，还是只按流程配置自动抄送。
- 附件上传权限是否由节点单独配置，还是二期先采用发起人和当前办理人可上传。
- 超时提醒的扫描频率、提醒间隔和最大提醒次数。

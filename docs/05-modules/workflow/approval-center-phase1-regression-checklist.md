# 审批中心一期核心回归清单

本文用于审批中心一期后续改动后的人工回归抽样。目标是覆盖核心闭环，防止修复单点问题时破坏列表、抽屉、选人、字段权限和流程流转。

本清单只覆盖一期能力，不把二期的会签、或签、条件分支、抄送、撤回、催办和超时提醒纳入必测范围。

## 回归触发规则

- 修改审批运行时抽屉、表单渲染、字段权限、审批动作、审批人解析或 `workflow` API 时，必须执行“主链路回归”和相关专项回归。
- 修改审批中心列表、`BaseTable`、`useTable`、`defineTableColumns`、分页、筛选、排序或列宽持久化时，必须执行“列表与分页”回归，并抽样检查一个系统管理列表。
- 修改 `UserPicker`、组织机构、角色、部门岗位或直属上级能力时，必须执行“选人与审批人解析”回归。
- 修改表单设计、流程设计、发布、新建版本、历史版本或设计器抽屉时，必须执行“设计与发布”回归。
- 仅修改文案、局部样式或文档时，可按影响范围抽样，不需要全量回归。

## 基础数据准备

- 至少准备一个普通申请人、一个部门负责人、一个直属上级、一个角色审批人、一个部门岗位审批人。
- 申请人必须维护主部门；部门必须维护唯一部门负责人；申请人在主部门关系中必须维护直属上级。
- 至少准备一个系统角色并分配 1 人，再准备一个系统角色并分配 2 人，用于验证单人和多人选择。
- 至少准备一个可作为审批岗位的部门角色，并分配 1 人和 2 人两种测试数据。
- 至少准备一个表单，包含必填字段、只读字段、隐藏字段、日期/文本等常用字段。
- 至少准备一个简易流程，覆盖发起节点、普通审批节点和结束节点。

## 主链路回归

- 新建表单草稿，设计字段，保存后页面不关闭，字段内容不丢失。
- 发布表单后，查看设计只能查看，不能保存。
- 新建流程草稿，绑定分类和表单，配置简易节点，配置字段权限。
- 发布流程后，发起申请页面只显示最新发布版本，旧版本只能从历史版本入口查看。
- 从发起申请页面提交申请，不先保存草稿，也必须能在“我的已办”和“我发起的”查到记录。
- 从发起申请页面保存草稿，草稿进入“我的待办”，再次打开后可以继续编辑并提交。
- 审批人通过后，流程进入下一节点；最后一个审批节点通过后，流程结束并显示结束节点。
- 审批人不通过后，流程结束，状态和审批意见均显示“不通过”。

## 运行时表单抽屉

- 发起申请：从“发起申请”页面打开流程，抽屉宽度 90%，左侧表单约 60%，右侧审批信息约 40%。
- 抽屉打开：打开过程中不应明显中途卡顿；表单可在抽屉打开后再完成渲染。
- 点击遮罩：点击灰色遮罩可以关闭抽屉，未提交的数据按当前交互预期处理。
- 表单展示：隐藏业务标识和申请标题，申请标题默认值为“当前登录人姓名的流程名称”。
- 表单信息：表单区域直接展示表单，不显示多余流程摘要、统计卡片或外层重复边框。
- 审批意见输入：待办办理时固定在左侧表单底部，标签在输入框左侧，和普通表单字段风格一致。
- 只读详情：从“我的已办”和“我发起的”打开详情，表单只读，不显示底部操作栏。
- 右侧辅助区：默认显示“审批意见”，Tab 头固定，内容超长时只滚动 Tab 内容。
- 审批意见时间线：显示审批意见、审批人、审批时间、审批结果，倒序/顺序应符合当前设计约定，结束流程显示“流程结束”节点。
- 传阅 Tab：一期没有传阅数据时显示空状态，不影响主流程。

## 审批动作

- 保存：发起申请保存后进入“我的待办”，任务类型为待提交。
- 提交：发起申请直接提交后进入下一审批环节，发起人已办记录存在。
- 通过：审批意见为空时默认写入“同意”，记录在右侧“审批意见”中。
- 不通过：审批意见为空时默认写入“不同意”，流程结束并显示结束节点。
- 退回：先校验审批意见必填，再弹出退回节点选择；目标节点来自后端返回的可退回节点列表。
- 退回流转：退回到上一个环节的执行人，不退给当前办理人自己，除非上一个环节执行人本来就是自己。
- 转办：审批意见必填，直接打开 `UserPicker` 单选人员，提交后目标人员可收到待办。
- 加签：审批意见必填，直接打开 `UserPicker` 单选人员，提交后加签人可收到待办。
- 重复提交：保存、提交、通过、不通过、退回、转办、加签过程中按钮应有 loading 或禁用状态，避免重复提交。

## 选人与审批人解析

- 指定人员：运行时直接流转到配置人员，待办只出现在该人员名下。
- 指定角色：角色下单人时直接流转；角色下多人时，在当前办理人点击提交/通过时选择下一审批人。
- 指定角色兜底：角色下没有有效用户时，才允许走审批人自选兜底，并给出提醒。
- 部门负责人：只解析当前提交人所在主部门的负责人，不能把所有部门负责人查出来。
- 部门岗位：只解析规则指定部门岗位下的有效人员；多人时提交/通过时选择具体人员，不直接派给多人抢办。
- 发起人直属上级：按当前提交人的直属上级解析，不用部门负责人替代。
- 审批人自选：配置为自选或下一步执行人为空时，在提交/通过时打开组织机构人员选择器。
- `UserPicker`：弹窗尺寸、部门树、角色、分页、搜索、已选列表、单选行为正常。
- 选择接口：人员选择类接口不依赖业务按钮授权，只按租户和数据范围过滤。

## 列表与分页

- 发起申请：可搜索可发起流程，流程卡片全部展示，不分页。
- 发起申请：查询和重置按钮位于查询输入框后方，白色内容区域高度自适应并铺满外层容器。
- 我的待办：分页、筛选、排序正常，发起人和当前处理人显示姓名，不显示审批编号。
- 我的已办：分页、筛选、排序正常，发起人和办理人显示姓名，不显示审批编号。
- 我的已办：已办理完的发起提交任务，任务类型应显示已提交或符合当前文案约定，不显示待提交。
- 我发起的：分页、筛选、排序正常，不显示审批编号。
- 我发起的：已结束实例当前节点显示“已结束”，当前处理人为空。
- 列表表头：审批中心列表筛选、排序复用 `BaseTable` 表头能力，不额外放页面顶部搜索区。
- 操作列：操作按钮样式、颜色、宽度和系统管理列表保持一致；删除按钮为红色危险样式。
- 分页回归：如果修改分页、表格或列宽逻辑，必须同时检查用户管理列表分页没有被破坏。

## 设计与发布

- 流程分类：新增、编辑、删除、筛选和排序正常；删除需要二次确认。
- 表单设计：列表只显示最新版本，历史版本通过入口查看。
- 表单设计：草稿可编辑，字段配置保存后不新增重复草稿版本。
- 表单设计：已发布查看设计不显示保存按钮，字段权限只能查看不能保存。
- 表单设计历史版本：流程分类等统一信息放在表头上方，不在列表重复显示；查看设计抽屉层级高于历史版本抽屉。
- 流程设计：列表只显示最新版本，历史版本通过入口查看。
- 流程设计：草稿可编辑，版本号、流程分类等发布后不可操作。
- 流程设计：已发布查看设计不显示保存按钮，设计器区域撑满容器。
- 流程设计历史版本：流程分类、设计器等统一信息放在表头上方，不在列表重复显示；查看设计抽屉层级高于历史版本抽屉。
- 单草稿版本规则：同一表单编码或流程编码存在草稿版本时，列表不显示“新建版本”，直接调用新建版本接口也应被后端拒绝。
- 新建版本：删除未发布的新版本后，再次新建版本不应因版本号冲突报错。
- 发布规则：同一个流程新版本发布后，旧版本废弃；发起申请只展示最新发布版本。
- BPMN 设计器：可查看/编辑状态正确，已发布只读；基础节点创建能力正常。
- 简易设计器：包含发起申请节点、审批节点和结束节点；发起申请节点可配置字段权限。

## 字段权限与表单校验

- 发起申请节点字段权限生效：必填、只读、隐藏按配置执行。
- 审批节点字段权限生效：当前节点只允许编辑可编辑字段，只读字段提交修改时后端忽略或拒绝，隐藏字段不展示。
- 必填校验：发起、草稿提交、审批通过、退回、转办、加签时，表单必填字段和审批意见必填规则均生效。
- 已发布流程字段权限只读：不能保存字段权限配置。
- FormCreate 渲染：常见输入、日期、选择类字段正常回显和提交。

## 权限与菜单

- 审批中心菜单按实际前端组件路径和后端权限点生成，不保留旧 `/workflow/approval` 或 `approval:*`。
- 租户管理员可见菜单和按钮符合授权结果，不暴露写死的系统内置能力。
- 操作按钮按权限显示，无权限时不显示入口。
- 日志按租户隔离；超级管理员查看日志范围按系统现有规则执行。

## 异常与边界

- 下一审批人为空：只有在角色/岗位/组织关系确实无法解析时，才提示并进入审批人自选兜底。
- 最后节点通过：流程直接结束，不再弹出下一审批人选择。
- 当前用户无待办：待办列表为空状态正常。
- 历史脏数据：开发阶段不为历史错乱数据增加兼容分支，重点保证新数据正确。
- 接口失败：保存、提交、审批动作失败时，按钮 loading 释放，抽屉不应进入假成功状态。

## 最低验证命令

前端代码变更后至少执行：

```powershell
pnpm.cmd typecheck
```

涉及构建、路由、全局样式、依赖或公共组件时追加执行：

```powershell
pnpm.cmd build
```

后端代码变更后至少执行：

```powershell
.\mvnw.cmd -q -DskipTests compile
```

数据库或初始化 SQL 变更后，必须同步检查 `sql/建表脚本.sql`、权限初始化 SQL 和相关模块文档。

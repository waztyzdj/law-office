# 审批中心二期设计文档

## 文档目的

本文用于固定审批中心二期的范围边界、设计原则、功能清单、数据与接口方向、页面改造点和验收口径。二期不再承接所有“后续能力”，只聚焦审批运行时增强和日常协同能力，避免交付范围过大。

## 阶段定位

二期在一期审批闭环基础上增强“流程怎么走”和“审批过程怎么协同”：

- 流程结构从顺序审批扩展到条件分支、会签、或签。
- 审批动作从通过、不通过、退回、转办、加签扩展到抄送、撤回、催办和超时提醒。
- 审批过程接入消息通知、附件和业务文档中心。
- 审批详情补齐流程图高亮，提升运行态可读性。
- 扩展 BPMN 能力时同步补齐 BPMN XML 安全校验和白名单限制。

## 二期范围

二期必须完成以下能力：

1. 条件分支
2. 会签
3. 或签
4. 抄送
5. 撤回
6. 催办
7. 超时提醒
8. 审批消息通知
9. 审批附件和业务文档中心联动
10. 流程图高亮当前节点
11. BPMN XML 安全校验和白名单限制

## 非二期范围

以下能力不进入二期，放入三期规划：

- 审批模板复制
- 流程版本迁移
- 流程实例管理员干预
- 审批统计和报表
- 流程监控大屏
- 移动端适配
- 打印、导出、归档
- 外部系统回调

## 设计原则

- 复用一期 `wf_*` 运行时表和 Flowable 集成方式，不直接暴露 `ACT_*` 表给前端。
- 新增能力必须保持租户隔离、数据权限和审批详情访问权校验。
- 接口继续使用 `/workflow` 前缀和 `POST + body` 风格。
- 条件分支、会签、或签必须同时支持简单设计器和 BPMN 发布校验；简单设计器不能表达的高级能力必须明确限制。
- 消息、附件、文档中心联动优先复用现有消息模块、文件模块和业务文档 Provider 扩展点。
- 二期新增状态、动作、枚举必须同步 SQL、后端常量、前端常量、接口文档和模块文档。

## 功能设计

### 条件分支

目标：

- 支持按表单字段、发起人、部门、金额等运行时变量决定后续流转路径。
- 简单设计器支持常用条件分支；BPMN 设计器支持白名单范围内的排他网关。

关键规则：

- 条件表达式必须后端校验和执行，不能信任前端传入的计算结果。
- 多个分支命中时按配置优先级选择；没有命中时必须配置默认分支。
- 发布流程时校验所有分支都可到达结束节点，避免悬空流程。

建议落库：

- 在 `wf_process_node_config` 或新增分支配置表中保存条件配置快照。
- 简单设计器 `node_json` 扩展 `branch`、`conditions`、`priority` 和 `defaultBranch`。

### 会签

目标：

- 一个节点可分配多个审批人，所有审批人完成后才进入下一节点。
- 支持通过比例或全员通过两种完成策略，二期默认优先实现全员通过。

关键规则：

- 任一会签人不通过时是否直接结束流程，需要在节点配置中明确。
- 会签任务必须能在待办、已办、详情和审批记录中展示每个参与人的办理结果。
- 会签审批人范围仍复用一期审批人解析能力和人员选择器。

### 或签

目标：

- 一个节点可分配多个审批人，任一审批人办理后即可进入下一节点。

关键规则：

- 首个有效办理人提交后，其它同节点待办取消。
- 审批记录保留已取消任务的系统记录，避免详情页看不出任务变化。
- 或签不能和一期默认“多人时由上一环节选择单人”混淆，流程节点必须显式配置或签策略。

### 抄送

目标：

- 发起、审批通过、流程结束等节点可向指定人员、角色或部门发送抄送。
- 被抄送人可查看审批详情，但不能办理审批任务。

关键规则：

- 抄送记录必须落库，作为审批详情访问权来源之一。
- 抄送范围支持固定配置和运行时选择，运行时选择必须复用人员选择器。
- 运行时手动抄送允许流程实例访问权用户在审批详情/办理页选择组织架构人员发起抄送；仅授予查看权，不产生待办，不改变流程状态，不允许按角色选择。
- 抄送不改变流程状态。

### 撤回

目标：

- 发起人在满足条件时撤回审批，实例进入已撤回终态。

关键规则：

- 已结束、已不通过、已被管理员干预的流程不能撤回。
- 是否允许“下一节点已办理后撤回”必须明确，二期建议只允许下一审批人未办理前撤回。
- 撤回必须取消当前待办和候选记录，并写审批记录。

### 催办与超时提醒

目标：

- 发起人或有权限人员可对当前待办执行催办。
- 节点可配置超时时间，超时后自动发送提醒。

关键规则：

- 催办只发送提醒和记录动作，不改变流程状态。
- 超时提醒需要防重复触发，建议按任务维度记录最近提醒时间和提醒次数。
- 二期只做提醒，不做自动跳过、自动同意或自动升级。

### 审批消息通知

目标：

- 审批待办、通过、不通过、退回、转办、加签、抄送、撤回、催办、超时等动作触发站内消息。

关键规则：

- 优先复用消息模块，不在工作流模块重复实现消息中心。
- 消息必须携带业务跳转信息，跳转后仍由审批详情接口做权限校验。
- 消息发送失败不应破坏主审批事务；失败需要有可排查日志。

### 审批附件和业务文档中心联动

目标：

- 发起和审批过程中支持上传、查看、删除附件。
- 审批相关文件可进入业务文档中心，遵守文档中心权限和归档规则。

关键规则：

- 附件必须复用文件模块上传、下载、预览和鉴权能力。
- 业务文档访问必须通过 `IBusinessDocumentProvider.canAccess(...)` 校验。
- 不同节点的附件新增、删除权限可受字段权限或节点动作权限控制。

### 流程图高亮当前节点

目标：

- 审批详情展示流程图，并高亮当前节点、已完成节点、退回路径和结束状态。

关键规则：

- 高亮信息以后端实例状态、任务状态和审批记录为准。
- 流程已结束时必须显示结束状态，不再显示悬空待办。
- 简单设计器和 BPMN 设计器需要统一输出前端可渲染的节点、边和状态。

### BPMN XML 安全校验和白名单限制

目标：

- 扩展 BPMN 能力时，防止引入脚本任务、服务任务、监听器表达式等高风险元素。

关键规则：

- 发布前必须解析 BPMN XML 并执行元素白名单校验。
- 二期允许的 BPMN 元素优先限制为开始事件、结束事件、用户任务、顺序流、排他网关、并行网关以及必要的扩展属性。
- 禁止脚本、外部调用、任意表达式执行和未审核监听器。

## 接口方向

二期接口仍使用 `/workflow` 前缀，参数放 body。建议新增或扩展：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/task/withdraw` | 撤回审批 |
| `POST` | `/task/urge` | 催办当前审批任务 |
| `POST` | `/cc/page` | 查询我的抄送 |
| `POST` | `/cc/read` | 标记抄送已读 |
| `POST` | `/cc/send` | 手动抄送审批实例 |
| `POST` | `/instance/detail` | 查询审批详情，响应包含 `ccRecords` 抄送记录 |
| `POST` | `/instance/diagram` | 查询实例流程图和节点高亮状态 |
| `POST` | `/attachment/page` | 查询审批附件 |
| `POST` | `/attachment/bind` | 绑定已上传文件到审批实例或任务 |
| `POST` | `/attachment/delete` | 删除审批附件 |

具体请求、响应字段在进入开发前补充到 `docs/04-api/`。

## 页面改造

### 管理端

- 简单设计器增加条件分支、会签、或签、抄送和超时配置。
- BPMN 设计器发布前展示安全校验结果。
- 节点配置增加办理策略、超时提醒、抄送配置。

### 用户端

- 我的待办支持会签、或签任务展示。
- 审批详情增加流程图 Tab 或右侧辅助区域入口。
- 审批详情增加附件区域和抄送信息。
- 增加“我的抄送”入口。
- 发起人可在符合条件时执行撤回。
- 当前处理人或发起人可执行催办。

## 验收口径

- 一期核心闭环仍全部可用。
- 顺序流程、条件流程、会签流程、或签流程均可完成端到端流转。
- 抄送人只能查看，不能办理。
- 撤回后当前待办被正确取消，审批记录可追溯。
- 催办和超时提醒生成消息，但不改变流程状态。
- 附件下载、预览和文档中心访问均通过后端权限校验。
- 流程图高亮与任务状态一致。
- 发布含高风险 BPMN 元素的流程必须被拒绝。

## 实施顺序

1. 补充 SQL、枚举、接口文档和权限码设计。
2. 实现 BPMN XML 白名单校验。
3. 扩展流程设计器节点模型，支持条件分支、会签、或签。
4. 后端扩展任务同步、审批记录和运行时流转。
5. 接入抄送、撤回、催办和超时提醒。
6. 接入消息通知。
7. 接入附件和业务文档中心。
8. 实现流程图高亮。
9. 执行一期回归和二期专项验收。

## 待确认事项

- 会签是否一期只做全员通过，还是同步支持通过比例。
- 撤回是否允许下一审批人已办理后撤回。
- 抄送是否需要支持发起时手动选择。
- 超时提醒是否需要工作时间日历，二期建议先按自然时间计算。
- 附件是否支持按节点限制上传数量、大小和类型。

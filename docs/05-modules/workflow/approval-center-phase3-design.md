# 审批中心三期规划文档

## 文档目的

本文用于固定审批中心三期的规划边界。三期不承接二期运行时增强的核心流转能力，而是面向流程治理、模板复用、输出下载和归档留存能力。

## 阶段定位

三期在一期闭环和二期运行时增强稳定后建设“管理和生态能力”：

- 管理员可以治理异常流程和模板复用。
- 审批结果可以打印、下载、归档。

## 三期范围

三期规划以下能力：

1. 审批模板复制
2. 流程监控
3. 打印、下载、归档

## 非三期范围

以下内容不作为三期默认范围：

- 新增复杂业务域审批，例如案件、合同、财务的专属审批规则；这类能力应由对应业务模块提出。
- 引入独立低代码平台或替换当前 FormCreate、Flowable 技术路径。
- 开放任意脚本、任意外部服务任务或用户自定义代码执行。
- 流程版本迁移不作为三期范围；已发起实例默认按发起时的流程版本继续流转，新发起实例使用最新发布版本。
- 审批统计和报表、监控大屏、移动端专项适配、外部系统回调不作为三期范围，统一移入后续规划；后续需要时单独补充需求、数据模型、权限和验收口径。

## 功能规划

### 审批模板复制

目标：

- 管理员可基于已有流程快速复制新模板，包括流程节点、字段权限、发起权限和抄送配置；复制时可继续绑定原表单，也可改绑其他已发布表单。

关键规则：

- 复制后必须生成新的流程模板，状态为草稿，版本号从 `1` 开始，不影响原模板。
- 复制时必须重新确认流程分类、绑定表单、流程编码和流程名称；流程编码在同租户内不能与任何未删除版本冲突。
- 绑定表单可选择来源表单或其他已发布表单；选择来源表单时复制字段权限，改绑其他表单时不复制字段权限。
- 复制范围包含流程设计内容、节点配置、发起权限、抄送配置、超时配置和条件分支配置；字段权限仅在绑定来源表单时复制。
- 复制范围不包含流程实例、任务、审批记录、分支命中记录、附件、消息、催办记录、超时提醒记录和 Flowable 部署数据。
- 复制后的 BPMN 流程仍需在发布时重新经过 BPMN 安全校验，不复用来源流程的发布状态和部署标识。
- 复制行为必须写管理日志；第一版在新流程备注中记录来源模板，后续若需要复制审计报表，再补独立复制记录表。

业务边界：

- 只支持同租户内复制，不支持跨租户复制。
- 复制是定义侧能力，只在流程管理中使用，不在运行时审批详情中开放。
- 复制出的模板是独立模板，不进入来源模板的历史版本链；来源模板后续修改、发布或删除，不影响已复制模板。
- 改绑其他表单时，节点流转配置仍复制，但字段权限需要管理员在新流程草稿中重新配置。
- 复制不自动发布，不自动生成菜单，不自动调整发起权限之外的系统权限。

第一版交互：

- 流程定义列表提供“复制模板”操作。
- 点击后弹出复制模板表单，默认带出来源流程分类、来源绑定表单并生成建议流程编码，管理员可修改流程分类、绑定表单、流程编码、流程名称和备注。
- 提交成功后刷新流程定义列表，新模板以草稿状态显示。

验收场景：

- 基于已发布流程复制模板，填写新的流程编码后，生成新的草稿流程，原流程不发生变化。
- 复制时继续绑定原表单，新流程包含来源流程的节点配置、字段权限、发起权限、抄送、超时和条件分支配置。
- 复制时改绑其他表单，新流程包含来源流程的节点配置、发起权限、抄送、超时和条件分支配置，但不复制字段权限。
- 使用已存在的流程编码复制时，后端拒绝并返回明确提示。
- 复制后的 BPMN 流程发布时仍执行 BPMN 安全校验，且没有来源流程的 Flowable 部署标识。
- 复制后不产生任何流程实例、待办、审批记录、附件或消息。
- 复制行为能在操作日志中追溯，复制后的流程备注能看到来源模板信息。

#### 表单模板复制

目标：

- 管理员可基于已有表单快速复制出一份新的表单模板，用于相似业务表单的二次设计。

关键规则：

- 复制后生成新的表单定义，状态为草稿，版本号从 `1` 开始，不进入来源表单的历史版本链。
- 复制时必须重新确认表单分类、表单编码和表单名称；表单编码在同租户内不能与任何未删除版本冲突。
- 复制范围包含 `schema_json` 和 `option_json`，即 FormCreate 规则和表单选项。
- 复制范围不包含表单实例、流程引用、字段权限、审批实例、附件和消息。
- 复制后的表单不自动发布，不自动绑定流程；管理员可进入表单设计器继续调整。
- 复制行为必须写管理日志；第一版在新表单备注中记录来源表单，后续若需要复制审计报表，再补独立复制记录表。

业务边界：

- 只支持同租户内复制，不支持跨租户复制。
- 复制是定义侧能力，只在表单设计中使用，不在流程运行时开放。
- 来源表单后续修改、发布、禁用或删除，不影响已复制出的表单模板。
- 表单复制不会自动同步任何已绑定流程；如流程需要使用新表单，应在新建或复制流程时手动选择。

第一版交互：

- 表单设计列表提供“复制模板”操作。
- 点击后弹出复制模板表单，默认带出来源表单分类并生成建议表单编码和表单名称，管理员可修改表单分类、表单编码、表单名称和备注。
- 提交成功后刷新表单设计列表，新表单以草稿状态显示。

验收场景：

- 基于已发布表单复制模板，填写新的表单编码后，生成新的草稿表单，原表单不发生变化。
- 基于草稿表单复制模板，也生成独立草稿表单，不进入原表单版本链。
- 使用已存在的表单编码复制时，后端拒绝并返回明确提示。
- 复制后的表单可进入表单设计器继续编辑，发布前仍按表单发布规则校验。
- 复制后不产生任何流程引用、表单实例、审批实例、附件或消息。
- 复制行为能在操作日志中追溯，复制后的表单备注能看到来源表单信息。

### 流程监控

目标：

- 管理员可在权限范围内查看流程运行情况，并对异常流程进行必要维护，例如改派当前处理人、终止流程、补发通知。

关键规则：

- 菜单名称统一为“流程监控”，用于流程运行态查看和异常流程维护。
- 权限只分两类：查看流程监控和维护流程监控。
- 查看权限允许进入流程监控列表、查看流程详情、审批记录、附件和流程图。
- 维护权限允许对未结束流程执行改派、终止、补发通知等维护动作。
- 管理员维护动作不等同于审批动作，不允许代替审批人通过、不通过、退回、转办或加签。
- 所有维护动作必须填写原因，并记录操作人、操作时间、动作类型、动作前后关键数据和结果。
- 维护记录必须在审批详情中可见，不能静默修改流程状态或待办归属。
- 所有查询和维护必须校验租户、权限和数据范围。

业务边界：

- 第一版只处理运行中或异常未结束流程；已结束、已终止、已撤回实例只允许查看，不允许再次维护。
- 第一版不修改表单数据，不删除审批记录，不删除附件，不恢复已结束流程。
- 第一版不支持流程版本迁移，不支持跨流程模板迁移，不支持重新打开已结束流程。
- 第一版不支持批量改派、批量终止，避免管理员误操作扩大影响。
- 改派只作用于当前待办任务，不改变已办记录，不改变流程定义和节点配置。
- 会签/或签同组内同一用户只能持有一条有效待办；改派目标人若已存在同组待办，后端拒绝改派，避免一人代表多票造成责任和进度歧义。
- 终止会结束流程实例并取消所有未完成待办；终止后不允许继续办理。
- 补发通知只重新发送当前有效待办通知，不新增待办、不改变流程状态。
- 抄送人、历史审批人等只有查看权的用户不能执行维护动作。

第一版功能：

- 流程监控页面采用左树右表结构：
  - 左侧树根节点为“全部流程”，其下一级节点为流程分类，二级节点为该分类下最新已发布版本的流程定义。
  - 点击“全部流程”虚拟节点时，用于查看所有流程实例。
  - 点击流程分类时，右侧展示该分类下所有流程定义产生的流程实例。
  - 点击流程定义时，右侧展示该流程定义编码下所有版本产生的流程实例；树节点只展示流程名称，不展示版本号，查询条件使用流程定义编码，不使用最新版本 ID。
- 流程监控列表：按实例标题、实例编号、流程名称、流程分类、流程编码、发起人、当前节点、当前处理人、状态、发起时间筛选，默认按发起时间或更新时间倒序。
- 流程监控列表保留流程版本字段，便于管理员识别实例来自哪个历史版本。
- 流程详情查看：复用审批详情展示表单快照、审批记录、附件、流程图和维护记录。
- 管理员改派：选择一个当前待办任务，将处理人改派给另一个用户，必须填写原因。
- 管理员终止：终止未结束流程，取消当前所有待办，必须填写原因。
- 补发通知：对当前待办处理人补发待办提醒或系统消息，必须记录补发动作。

数据模型设计：

- 新增 `wf_admin_operation_record` 管理员维护记录表。
- 核心字段建议：
  - `id`：主键。
  - `tenant_id`：租户 ID。
  - `process_instance_id`：流程实例 ID。
  - `task_id`：关联任务 ID，终止流程时可为空。
  - `operation_type`：维护动作，取值 `reassign`、`terminate`、`resend_notice`。
  - `operation_reason`：维护原因，必填。
  - `before_snapshot_json`：动作前关键数据快照，例如原处理人、任务状态、流程状态。
  - `after_snapshot_json`：动作后关键数据快照，例如新处理人、终止状态、通知结果。
  - `operator_user_id`、`operator_username`、`operator_realname`：维护操作人快照。
  - `operate_time`：维护时间。
  - `status`：维护结果，取值 `success`、`failed`。
  - `error_message`：失败原因。
  - 审计字段和逻辑删除字段按项目统一规范保留。
- 维护记录不替代 `wf_approval_record` 审批记录；审批详情展示时可将管理员维护记录作为单独阶段或单独标识展示。

接口设计：

- `POST /workflow/admin/monitor/page`：分页查询流程监控列表，需要查看流程监控权限。
  - 支持 `categoryId` 按流程分类过滤，返回该分类下所有流程定义版本产生的实例。
  - 支持 `processKey` 按流程定义编码过滤，返回该流程所有版本产生的实例。
- `POST /workflow/admin/monitor/detail`：查询流程监控详情，需要查看流程监控权限。
- `POST /workflow/admin/monitor/reassign`：管理员改派当前待办，需要维护流程监控权限。
- `POST /workflow/admin/monitor/terminate`：管理员终止流程，需要维护流程监控权限。
- `POST /workflow/admin/monitor/resend-notice`：补发当前待办通知，需要维护流程监控权限。
- `POST /workflow/admin/monitor/operation-records`：查询维护记录，需要查看流程监控权限。

权限设计：

- 菜单查看权限：`workflow:monitor:view`。
- 维护动作权限：`workflow:monitor:manage`。

验收场景：

- 有查看权限的用户可以进入流程监控列表并查看实例详情，但不能看到或执行维护按钮。
- 左侧选择“全部流程”时，右侧展示所有流程实例；选择分类时，右侧仅展示该分类下流程实例。
- 左侧选择最新已发布流程定义节点时，右侧展示该流程编码下所有版本产生的实例，列表中可看到具体版本号。
- 有维护权限的用户可以对运行中实例的当前待办执行改派，原办理人待办取消，新办理人收到待办或通知。
- 改派必须填写原因；原因为空时后端拒绝。
- 有维护权限的用户可以终止运行中实例，终止后当前待办全部取消，流程详情显示管理员终止记录。
- 已结束、已撤回、已终止实例不显示维护动作，直接调用维护接口也会被后端拒绝。
- 补发通知只给当前有效待办处理人发送消息，不新增待办、不改变流程状态。
- 无维护权限用户调用改派、终止、补发通知接口时后端拒绝。
- 管理员维护记录可在审批详情中查看，包含操作人、时间、动作类型和原因。

### 打印、下载、流程归档

目标：

- 支持将审批详情、表单数据、审批记录和附件输出为可留存材料。
- 将已结束审批实例转为正式可审计档案，区分日常流程历史和档案留存口径。

关键规则：

- 打印和下载必须按审批详情访问权校验。
- 下载内容应使用实例快照，避免后续表单变化影响历史输出。
- 第一版打印、下载只允许审批通过并结束的实例使用；运行中、驳回、撤回、草稿实例不提供正式输出入口。
- 第一版只提供一个“下载”入口，下载审批单 PDF + 原始附件 ZIP 材料包，不单独暴露 PDF 按钮。
- ZIP 材料包内包含审批单 PDF 和原始附件文件，附件放入 `附件/` 目录；审批单 PDF 输出表单内容、审批记录和附件清单。
- 下载接口属于审批运行时能力，放在 `RuntimeController`，采用 `POST + RequestBody` 风格，实例 ID 放请求体。
- 正常结束的流程自动归档；正常结束指按流程定义自然到达结束节点的实例，归档记录保留原审批结果。
- 发起人撤回结束的流程不归档，也不进入未归档待处理池。
- 管理员终止的流程不自动归档，由流程管理员或档案管理员根据业务需要手动归档。
- 归档不改变流程实例审批状态，不重新计算流程，不新增待办，不修改审批记录。
- 归档后流程表单、审批记录和附件均按只读档案口径展示；普通运行时不允许继续新增、删除或替换附件。
- 第一版归档后下载仍复用现有审批材料包生成能力，不单独保存二进制 ZIP；因为归档后附件只读，动态生成结果应保持稳定。后续如需电子档案固定件，再扩展归档文件关系。

归档权限：

- 流程正常结束时由系统自动归档，不需要人工权限。
- 流程监控中的手动归档按钮允许拥有“维护流程监控”权限的流程管理员使用。
- 流程归档菜单中的手动归档和批量归档允许拥有“维护流程归档”权限的档案管理员使用。
- 查看流程归档菜单和归档详情需要“查看流程归档”权限。

流程监控归档入口：

- 流程监控列表对已结束且未归档的流程实例显示“归档”按钮，包括已通过、已拒绝和已终止流程，用于补归档历史数据。
- 从流程监控进入的流程详情页，对已结束且未归档的流程实例显示“归档”按钮。
- 流程监控列表支持多选已结束且未归档流程实例后批量归档，也支持按当前查询条件归档；不符合归档状态的实例不可勾选，后端仍需要按相同状态边界再次校验。
- 已自动归档、已手动归档、撤回、运行中、草稿实例不显示归档按钮。
- 手动归档必须记录归档人、归档时间、归档来源和归档说明；第一版归档说明可选，后续如接入档案审核可改为必填。

流程归档菜单：

- 新增菜单“流程归档”，用于档案口径的归档查询、查看、下载和终止流程归档处理。
- 页面布局参考流程监控，左侧为两层流程定义树：
  - 根节点为“全部流程”。
  - 一级节点为流程分类。
  - 二级节点为该分类下最新已发布版本的流程定义；树节点只展示流程名称，不展示版本号。
  - 点击流程定义时，右侧按流程定义编码查询该流程所有版本的实例，不按最新版本 ID 查询。
- 右侧分为两个 Tab 页：
  - “已归档”：展示根据左侧树筛选后的归档流程实例。
  - “未归档”：展示根据左侧树筛选后的已结束且尚未归档流程实例，包括已通过、已拒绝和已终止流程，用于人工归档处理。
- 已归档列表提供“详情”和“下载”两个操作：
  - 详情复用类似流程监控的审批详情，只读展示表单快照、审批记录、附件、流程图、抄送记录和维护记录。
  - 下载复用审批材料包下载能力，打包下载审批单 PDF 和原始附件。
- 未归档列表支持逐个归档、勾选后按 ID 批量归档，也支持按当前查询条件批量归档；按查询条件批量归档单次最多处理 1000 条，超过时需要收窄查询条件。
- 未归档列表可提供详情查看，但详情保持只读；归档动作仍以列表按钮或详情中的明确归档按钮触发。

归档边界：

- 归档不是删除，也不是隐藏；我的已办、我发起的、我的抄送仍可按原权限查看历史实例。
- 已归档实例不应出现在我的待办，因为归档前流程必须已结束且不存在有效待办。
- 归档不生成新的抄送、催办、待办或系统审批动作。
- 归档不处理电子签章、档案编号规则、长期存储迁移、保管期限、借阅审批和销毁流程；这些属于后续档案管理能力。
- 第一版不提供撤销归档；若归档错误，先通过数据库或后续运维能力处理，避免普通页面反复改变档案状态。

## 后续规划

以下能力不纳入审批中心三期交付范围，后续如有明确业务场景再分别立项设计：

### 审批统计和报表

- 可提供审批数量、通过率、平均耗时、节点耗时、待办积压、超时数量等统计。
- 统计口径必须先定义，再开发报表；报表数据以 `wf_*` 业务表为准，不直接依赖 Flowable 历史表展示给前端。
- 涉及跨租户统计时必须遵守系统超级管理员和租户管理员边界。

### 监控大屏

- 可面向管理者展示流程运行态势，包括处理中、已结束、超时、积压和高频流程。
- 大屏只展示聚合信息，不暴露无权限查看的审批详情。
- 大屏查询必须考虑性能，必要时使用统计快照或定时汇总表。

### 移动端专项适配

- 可支持移动端查看待办、办理审批、查看详情、处理附件和消息跳转。
- 移动端优先复用现有接口，必要时新增轻量聚合接口。
- 表单渲染、附件预览、人员选择器和审批意见输入需要单独设计移动端交互。

### 第三方系统开放接口

- 可面向外部系统开放审批发起、办理、撤回、查询、附件、回调等能力。
- 开放接口必须单独设计应用接入、授权、签名、幂等、限流、审计、回调重试和租户隔离。
- 外部系统接入不复用后台管理端权限模型，不允许绕过审批中心运行时业务规则。

## 数据和接口方向

三期进入开发前，需要补充以下设计：

- 模板复制第一版通过流程备注和操作日志记录来源；若后续需要复制审计报表，再补来源字段或独立复制记录表。
- 流程监控维护记录表和权限码。
- 流程归档记录表和权限码。

接口仍遵循 `/workflow` 前缀和 `POST + body` 风格；文件下载、预览等资源型接口如需使用 path 参数，必须在接口文档中单独说明原因。

流程归档第一版建议新增 `wf_archive_record` 表：

- `id`：主键。
- `tenant_id`：租户 ID。
- `process_instance_id`：流程实例 ID，同一有效归档记录内唯一。
- `process_model_id`：流程模型版本 ID。
- `category_id`、`category_name`：归档时流程分类快照，`category_id` 对应 `wf_process_category.id`，用于归档列表按分类筛选和历史展示。
- `process_key`、`process_name`、`process_version`：归档时流程定义快照；按左侧流程定义树筛选时使用 `process_key` 覆盖该流程所有版本。
- `form_instance_id`、`form_definition_id`：表单实例和表单定义版本 ID，用于打开归档详情和生成材料包。
- `instance_title`、`instance_no`：归档时实例标题和流水号快照。
- `starter_user_id`、`starter_username`、`starter_realname`：发起人快照。
- `instance_status`：归档时流程实例状态，对应 `wf_process_instance.status`，例如 `approved`、`rejected`、`terminated`。
- `process_start_time`、`process_end_time`：归档时流程起止时间快照。
- `archive_source`：归档来源，取值 `auto`、`monitor_manual`、`archive_manual`。
- `archive_reason`：归档说明。
- `archiver_user_id`、`archiver_username`、`archiver_realname`：归档人快照；自动归档可记录为系统用户或流程最后处理人，具体实现阶段确认。
- `archive_time`：归档时间。
- 审计字段和逻辑删除字段按项目统一规范保留。

流程归档第一版接口方向：

- `POST /workflow/admin/archive/tree`：查询流程归档左侧流程树，需要查看流程归档权限。
- `POST /workflow/admin/archive/archived-page`：分页查询已归档实例，需要查看流程归档权限。
- `POST /workflow/admin/archive/unarchived-page`：分页查询已结束未归档实例，需要查看流程归档权限。
- `POST /workflow/admin/archive/detail`：查询归档详情，需要查看流程归档权限，详情结构复用审批详情聚合能力。
- `POST /workflow/admin/archive/diagram`：查询归档详情页流程图，需要查看流程归档权限；只允许已归档实例和未归档池中的已结束实例，不能借普通运行时图谱接口查看运行中流程。
- `POST /workflow/admin/archive/attachment/list`：查询归档详情页附件，需要查看流程归档权限；仅只读展示，不允许上传或删除。
- `POST /workflow/admin/archive/attachment/download`：下载归档详情页单个附件，需要查看流程归档权限，请求体使用 `id` 传审批附件 ID。
- `POST /workflow/admin/archive/attachment/download-all`：打包下载归档详情页附件，需要查看流程归档权限，不包含审批单 PDF。
- `POST /workflow/admin/archive/archive`：手动归档单个已结束未归档实例，需要维护流程归档权限。
- `POST /workflow/admin/archive/batch-archive`：按实例 ID 批量归档已勾选的已结束未归档实例，需要维护流程归档权限。
- `POST /workflow/admin/archive/batch-archive-by-query`：按未归档列表查询条件批量归档已结束未归档实例，需要维护流程归档权限。
- `POST /workflow/admin/archive/download`：下载归档材料包，需要查看流程归档权限并校验归档记录存在。
- 流程监控归档入口使用 `POST /workflow/admin/monitor/archive`、`POST /workflow/admin/monitor/batch-archive`、`POST /workflow/admin/monitor/batch-archive-by-query`，需要维护流程监控权限；业务规则仍由独立归档 Service 统一校验，避免规则分散。

流程归档权限码：

- `workflow:archive:view`：查看流程归档菜单、归档列表和归档详情。
- `workflow:archive:manage`：手动归档和批量归档。

## 验收口径

- 模板复制不会影响原流程和历史实例。
- 流程监控维护动作全程可审计，并展示在审批详情。
- 打印、下载、归档读取历史快照。
- 正常结束流程自动生成归档记录，归档后可在流程归档“已归档”页查询。
- 发起人撤回结束的流程不生成归档记录，也不出现在流程归档“未归档”页。
- 历史已结束但未归档流程，以及管理员终止后未归档流程，可在流程监控列表、流程监控详情或流程归档“未归档”页手动归档；流程监控列表可对符合状态的实例执行逐个归档、多选批量归档和按查询条件归档。
- 流程归档左侧选择全部流程、流程分类或流程定义时，已归档和未归档两个 Tab 均按同一范围筛选。
- 已归档列表点击详情可打开只读审批详情，能查看表单快照、审批记录、附件、流程图、抄送记录和维护记录。
- 已归档列表点击下载可下载审批单 PDF 和原始附件组成的材料包。
- 未归档列表可逐个归档、勾选多个实例按 ID 批量归档，也可按当前查询条件批量归档；无维护流程归档权限时不显示归档按钮，直接调用接口也会被拒绝。
- 已归档流程仍可在我的已办、我发起的、我的抄送中按原权限查看，但不出现在我的待办。

## 与二期的关系

三期依赖二期稳定的运行时事件、审批记录、附件和消息能力。若二期尚未完成，不应提前实现依赖这些事件的归档和输出能力，否则会造成口径返工。

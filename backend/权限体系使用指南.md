# 权限体系使用指南

## 一、概述

本系统采用基于角色的访问控制（RBAC）模型，结合JWT Token实现无状态的身份认证和权限验证。

### 核心特性
- ✅ 基于角色的权限管理
- ✅ JWT Token无状态认证
- ✅ 方法级别的权限控制（@RequiresPermissions注解）
- ✅ 支持AND/OR逻辑的权限组合验证
- ✅ 自动从数据库加载用户权限
- ⏳ Redis缓存支持（待集成）

## 二、数据库表结构

### 核心表说明

1. **sys_user** - 用户表
2. **sys_role** - 角色表
3. **sys_permission** - 权限表（菜单、按钮等）
4. **sys_user_role** - 用户角色关联表
5. **sys_role_permission** - 角色权限关联表

### 权限流程
```
用户(User) → 拥有多个角色(Role) → 角色拥有多个权限(Permission)
```

## 三、授权管理

### 1. 为用户分配角色

通过`UserService.assignRoles()`方法为用户分配角色：

```java
@Autowired
private IUserService userService;

// 为用户分配角色
List<String> roleIds = Arrays.asList("role1", "role2");
userService.assignRoles(userId, roleIds);
```

### 2. 为角色分配权限

通过`RoleService.assignPermissions()`方法为角色分配权限：

```java
@Autowired
private IRoleService roleService;

// 为角色分配权限
List<String> permissionIds = Arrays.asList("perm1", "perm2");
roleService.assignPermissions(roleId, permissionIds);
```

### 3. 获取用户权限

```java
// 获取用户的权限列表（完整信息）
List<Permission> permissions = userService.getUserPermissions(userId);

// 获取用户的权限编码列表（用于权限验证）
List<String> permissionCodes = userService.getUserPermissionCodes(userId);
```

## 五、权限验证

### 1. 使用@RequiresPermissions注解

在Controller方法上添加`@RequiresPermissions`注解，系统会自动验证用户权限。

#### 示例1：单个权限验证

```java
@GetMapping("/user/list")
@RequiresPermissions("user:list")
public BaseResult<List<User>> list() {
    // 只有拥有user:list权限的用户才能访问
    return userService.list();
}
```

#### 示例2：多个权限验证（AND逻辑）

```java
@PostMapping("/user/save")
@RequiresPermissions(value = {"user:list", "user:add"}, logical = RequiresPermissions.Logical.AND)
public BaseResult<User> save(@RequestBody User user) {
    // 需要同时拥有user:list和user:add权限
    return userService.save(user);
}
```

#### 示例3：多个权限验证（OR逻辑）

```java
@GetMapping("/data/export")
@RequiresPermissions(value = {"user:export", "role:export"}, logical = RequiresPermissions.Logical.OR)
public BaseResult<Void> export() {
    // 只需要拥有user:export或role:export任一权限即可
    return exportService.export();
}
```

### 2. 权限验证流程

```
请求到达 
  ↓
JwtAuthenticationFilter验证Token
  ↓
从数据库加载用户权限
  ↓
将权限列表设置到request属性中
  ↓
PermissionAspect拦截@RequiresPermissions注解
  ↓
验证用户是否拥有所需权限
  ↓
通过则执行业务逻辑，否则抛出异常
```

## 七、注意事项

### 1. 权限编码规范

建议采用`模块:操作`的格式，例如：
- `user:list` - 用户列表
- `user:add` - 用户新增
- `user:edit` - 用户编辑
- `user:delete` - 用户删除
- `role:list` - 角色列表

### 2. 性能优化（待集成Redis）

当前实现每次请求都会从数据库查询用户权限，后续将集成Redis缓存：
- 登录时将用户权限存入Redis
- JwtAuthenticationFilter从Redis读取权限
- 权限变更时清除Redis缓存

### 3. 异常处理

权限验证失败会抛出RuntimeException，建议在全局异常处理器中统一处理：

```java
@ExceptionHandler(RuntimeException.class)
public BaseResult<Void> handleRuntimeException(RuntimeException e) {
    if (e.getMessage().contains("权限不足")) {
        return BaseResult.error(403, "权限不足，无法访问该资源");
    }
    if (e.getMessage().contains("未登录")) {
        return BaseResult.error(401, "未登录或登录已过期");
    }
    return BaseResult.error(500, e.getMessage());
}
```

### 4. 安全配置

确保SecurityConfig中的过滤器配置正确：

```java
registration.addUrlPatterns("/api/*");  // 拦截/api/开头的请求
registration.addInitParameter("exclusions", "/api/auth/login");  // 排除登录接口
```

## 九、常见问题

### Q1: 如何查看当前用户拥有的权限？

A: 登录后返回的数据中包含permissions字段，或者调用`/auth/info`接口获取用户信息。

### Q2: 权限修改后为什么不生效？

A: 当前实现每次请求都会重新从数据库加载权限，所以会立即生效。集成Redis后需要注意缓存更新。

### Q3: 如何给超级管理员所有权限？

A: 可以在PermissionAspect中添加特殊判断，如果用户是超级管理员则直接放行。

### Q4: 按钮级别的权限如何控制？

A: 前端根据返回的permissions列表判断是否显示按钮，后端在对应接口上添加@RequiresPermissions注解。
